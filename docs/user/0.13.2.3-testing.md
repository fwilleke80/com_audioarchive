# 0.13.2.3: collection cleanup and visibility

Install the 0.13.2.3 installer over the current version, then reload the frontend so updated scripts load.

## Collections

Both Playlists and Sound Boards omit the account-storage label and Not now button. Browser-only mode retains a short persistence note. Revoke share link appears only when the selected owned collection has an active share link, and updates when the selection or sharing state changes.

The import action is now labelled Move browser collections to my account. Each completely imported collection is removed from browser storage after server acknowledgement. If a collection contains unavailable clips, the entire collection stays in the browser and no partial account copy is created. Other complete collections can still move. Failed requests or browser cleanup failures retain the source. Browser copies changed in another tab during import are also retained.

Retries of the same import in this version reuse the same account collection rather than adding duplicates. This does not remove duplicate collections previously created by older versions.

Test with two browser playlists and a Sound Board. Move them, reload, and confirm the completed imports are no longer offered. Try an unavailable clip and confirm its collection remains. Create a share link, switch between shared/unshared collections and revoke it; the revoke control should follow those changes.

## Clip visibility

Upload menu defaults and frontend forms use Public, Registered users and Private. Private is offered only when private uploads are allowed (or when editing an existing private clip).

Registered users uses Joomla's Registered view level by default. In Component Options → Frontend Contribution, include Registered in the allowed frontend access levels. If the upload menu restricts access levels too, include Registered there as well. The Registered users access level option permits mapping the preset to an appropriate alternative on customized sites. Do not map it to an access level available to guests.

Public uses Joomla's Public view level. Registered users uses the configured registered view level. Both persist as ordinary clips with the appropriate Joomla access level; Private keeps the existing owner/authorised-manager restriction. Category access, publication and scheduling continue to apply. Existing custom access levels are preserved and exposed as Custom access when editing such clips.

Test a published Registered users clip as its owner, another registered user, and a guest. The guest must not see or stream it, including through shared collections. Reopen its editor and confirm Registered users remains selected. Test fixed menu visibility with visitor selection disabled, and verify private creation still respects its component option.
