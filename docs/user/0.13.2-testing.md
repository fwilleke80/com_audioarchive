# Version 0.13.2: setup and testing

Install `pkg_audioarchive_v0-13-2.zip` over 0.13.1.1 using Joomla's extension installer. Back up the database and managed media first. Clear Joomla/browser caches after upgrading so the new JavaScript loads.

## Enable account collections

Open **Components → Punga Audio Archive → Options → Personal collections**. Change collection storage to **Saved to your account** (server storage). Browser storage remains the default for compatibility. Sign in with an ordinary user and open your Playlists or Sound Board menu item.

- Create, rename, reorder and delete playlists. Reload and sign into the same account in another browser: the collections should match.
- Create two named Sound Boards, assign different clips, switch between boards and set a default. Open a fresh browser session to check the default. Each existing tab remembers its own selection.
- If browser collections exist, use the explicit import prompt. As of 0.13.2.3, complete imports are moved into the account and removed from this browser. Collections containing unavailable clips remain wholly in the browser, with a notice. Reloading should not offer completed imports again.
- Sign in as another user: the first user's collections must not appear. Open two tabs for the same account, save a change in one, then edit the older tab. The older save must show a conflict; reload before trying again.
- Browser/server policy changes do not automatically migrate or delete data. Guest browser persistence can be disabled separately.

The User choice policy resolves the stored profile preference or configured default. The dedicated user-profile preference editor remains planned for 0.13.3; use server policy to test this release directly.

## Sharing

Use the existing share control for a saved account playlist or Sound Board to obtain a short link. Open it in another browser or as a guest. The collection opens temporarily; it does not replace the visitor's saved collection. Explicit add/replace controls remain available.

A link grants no additional clip permissions. Restricted, unpublished or private clips remain unavailable to unauthorized visitors. Revoke the link from the owner's collection controls and verify that the old URL stops resolving. Copying the link again before revocation reuses the same token. Collection sharing can be switched off in Options.

Browser-only JSON and URL sharing remain available. Performance recordings remain browser-local and still support JSON export/import with their board snapshot. Server-stored recordings and short recording share links are not included.

## Peak normalization

Install hotfix 0.13.2.1 if the normalization controls are missing. They are grouped under Playback and Downloads → Playback normalization.

Open **Options → Playback** and enable playback normalization. The default is off. Set the target peak, normally **−1 dBFS**; accepted targets are −60 through 0 dBFS. A clip's editor offers Inherit, Enabled and Disabled overrides, including frontend creation/editing.

Generate or regenerate waveform analysis for the clips you want to compare, and process the queued jobs. Existing waveform JSON has no measured peak until regenerated; upgrading does not trigger a mass regeneration. Peak measurement uses the original channels before downmixing and is stored in the waveform artifact.

Compare a quiet and a loud clip in the unified player, playlist, backend preview, Sound Board pads, chromatic sampler and recording playback. Test clip overrides, user volume/mute and switching between clips with and without analysis. Missing, stale, silent or malformed peak data falls back to ordinary playback. Original files and downloads remain unchanged.

This is sample-peak normalization, not loudness matching or limiting. Simultaneous voices can still overload their combined output. Browser Web Audio support/activation is required; unavailable initial audio processing falls back to ordinary playback.

### Normalized waveform display (0.13.2.2)

Waveform height follows the effective playback normalization gain, including the target and clip override. Both played and unplayed layers use the same scale. Volume and mute do not affect the waveform height. There is no separate switch. No additional regeneration is needed if the clip already has current peak metadata. Missing/stale metadata or disabled normalization retains the original scale. Stored waveform samples are unchanged. Mono downmix cancellation can still make a stereo waveform appear small.

## Recorder and frontend editor

Collapse the Recorder section below the Sound Board, reload, and verify it stays collapsed for that user in the current browser tab session. Expand it and repeat. Collapsing should not stop recording or playback.

On frontend Create Clip and Edit Clip pages, verify the CMS content Field insertion button is absent and the other editor controls work. The actual clip Custom Fields remain available. Also retry an ordinary user's quota-exceeding upload and check the explanatory rejection.

## Backup and restore

Portable archive export now includes account collections keyed by username and clip UUID. Restore resolves those identities; unresolved references produce warnings. Restored collections do not reactivate previous share tokens. When preference restoration is selected, default-board selection is restored too.

## Validation performed

Automated checks cover collection ownership and transactions, stale-tab rejection, private-clip filtering, share revocation, portable collection restore, quota/contribution policy, the previous Archive recursion regression, gain calculation and browser adapter logic. FFmpeg checks include anti-phase stereo, silence and peaks above 0 dBFS. PHP, JavaScript, XML, JSON and language files are checked before packaging.

A full Joomla/MySQL installation and interactive browser playback were not available in the build environment. The checks above are the remaining live-site acceptance tests; automated results do not substitute for them.
