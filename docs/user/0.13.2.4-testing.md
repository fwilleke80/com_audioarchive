# 0.13.2.4: frontend uploads, My clips and module fixes

Install the package over 0.13.2.3. Clear Joomla/browser caches if old styles or module output persist.

## Frontend upload processing

Keep Process Audio restricted to administrators. A successful frontend upload now opens a short progress page, processes the enabled analyses one job per request, and continues to the configured destination. The upload itself is already saved before processing starts. Analysis failure does not cause the uploaded clip to be lost or require another upload.

Keep the progress page open until it finishes. If you leave early, opening My clips in the same signed-in session resumes the captured jobs. The session receipt expires after 24 hours. JavaScript is required; this update does not install a Scheduled Task or a background daemon. Previously queued jobs from older versions, expired sessions and failed jobs can still be handled from backend Maintenance.

The processing endpoint requires POST, Joomla CSRF protection, a matching session receipt and current ownership of a non-trashed clip. It can process only the exact job IDs captured after that upload. It cannot create regeneration jobs, process another user's upload, or consume later administrator-queued jobs for the same clip. Completed requests are repeatable so a lost response cannot rerun completed jobs. General Process Audio ACL is unchanged.

Test as your ordinary contributor: upload an audio file with waveform/spectrum/frequency-profile generation enabled, wait for completion, and check My clips and the backend queue. Test navigating away and returning to My clips in the same session. Upload processing errors should remain visible; internal FFmpeg paths/errors stay in the administrator queue.

## Create Clip and My clips

When only one category is permitted by the combined contribution/menu/ACL rules, it is selected automatically and the selector is hidden. Multiple permitted categories retain the selector. Server-side checks still reject unauthorized category IDs.

My clips uses Archive table styling and the same shared minimal player layout. Its owner-specific status, visibility, processing details and edit/delete controls remain. The Actions heading is translated. Playback remains subject to the existing media ACL; owned unpublished clips can be previewed when the user has the corresponding editing permission, and inaccessible media is not exposed by a play button.

Processing uses a short summary such as Ready, Waiting for analysis or Analysis failed. Expand it to see individual states. On narrow screens the owner table remains horizontally scrollable rather than disappearing with Archive's desktop table.

## Module tag filters

- All selected tags: every distinct selected tag must be assigned to the clip.
- Any selected tag: at least one selected tag must be assigned.
- No eligible clips: the module displays No clips match the selected criteria.
- Clip of the day and random selection both operate only on the filtered eligible set.
- The tag selector now uses Joomla AJAX search, like the clip editor, without allowing creation of new tags in the module settings.

Test All and Any with two tags, seven tags, and a combination with no matches. Verify the result really has the required tags. Search for a tag that was previously absent from the module selector, save, and reopen to confirm its selection persists. Existing Joomla access, language, publication and category rules remain in force.
