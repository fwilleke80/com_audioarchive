# Version 0.13.2.7: iPhone playback and frequency profile

Install `pkg_audioarchive_v0-13-2-7.zip` over 0.13.2.6, then reload open Audio Archive pages. Keep playback normalisation enabled. No analysis regeneration is required.

## iPhone

The buffer player now requests a media-playback audio session before constructing/resuming Web Audio. WebKit documents that its default ambient Web Audio session can be silenced by the iPhone Silent switch, unlike native media playback. This missing setup is a plausible cause of the reported silence, but has not been confirmed on the reporter's device. See [WebKit issue 237322](https://bugs.webkit.org/show_bug.cgi?id=237322).

- Play a previously affected short clip with Silent mode both enabled and disabled. Verify audible output at 1x, 0.5x and 0.25x, plus pause/resume and seeking.
- Change speed while playing; smooth pitch changes and continuous cursor movement should remain as in 0.13.2.6.
- Test a playlist and the chromatic sampler. Leaving sampler mode must not change the audio session while another clip still owns it.
- Interrupt playback by switching apps, then return and retry. The player rechecks the context state after download/decode. Automatic playback through every phone-call/background scenario is not guaranteed by this patch.
- Repeat a quick playback check on the working macOS Safari and Chrome installations.

Session handling uses feature detection, tolerates missing/read-only APIs, and preserves an existing play-and-record session. Ordinary sound-board pad streaming is unchanged. Buffer loading limits and native fallback remain as described in the [0.13.2.6 notes](0.13.2.6-testing.md).

## Frequency profile

Open a clip with available frequency-profile data and select Frequency profile. Confirm the curve, filled area, grid and frequency labels appear. Switch to waveform/spectrum and back, then resize the page. A stray undefined gain reference, first present in the 0.13.2.2 renderer, has been removed. Waveform normalisation still applies only to the waveform drawing path.

## Verification

Run these from the source root:

```sh
node docs/developer/tests/audio-session.mjs
node docs/developer/tests/normalization.mjs
node docs/developer/tests/frequency-profile.mjs
node docs/developer/tests/waveform-normalization.mjs
```

The tests exercise session ownership/restoration, session setup before AudioContext creation, interruption during decoding, existing buffer transport behaviour and the actual frequency-profile/waveform drawing functions. Tests use deterministic browser/audio/canvas models. Real iPhone audio output and live Joomla rendering still require device testing.
